Единственный «живой RCE-кандидат», вокруг которого крутился весь разговор, оказался артефактом libFuzzer, а не дефектом MicroTeX. Доказательство железное — одна и та же библиотека MicroTeX, одни и те же входы:

┌──────────────────────────────────┬─────────────────┬────────────────┐
│              сборка              │ \substack{a\\b} │ \color{red}{x} │
├──────────────────────────────────┼─────────────────┼────────────────┤
│ argv harness (ASan+UBSan)        │ exit 0          │ exit 0         │
├──────────────────────────────────┼─────────────────┼────────────────┤
│ AFL non-persistent (ASan+UBSan)  │ exit 0          │ exit 0         │
├──────────────────────────────────┼─────────────────┼────────────────┤
│ harness_fuzz (ASan+UBSan+fuzzer) │ SEGV 0x0d       │ SEGV 0x0d      │
├──────────────────────────────────┼─────────────────┼────────────────┤
│ harness_fuzz (ASan-only+fuzzer)  │ SEGV 0x0d       │ SEGV 0x0d      │
└──────────────────────────────────┴─────────────────┴────────────────┘

Почему это железно:
1. argv и harness_fuzz используют идентичный ASan-аллокатор и отличаются ТОЛЬКО флагом -fsanitize=fuzzer. argv не падает никогда → это не heap-state / не UAF / не порча памяти.
2. Убрал UBSan — ничего не изменилось → это не UBSan vptr.
3. \color{red}{x} — это документированное «gotcha #2» ложное срабатывание из SESSION_FINDINGS.md, и оно байт-в-байт идентично \substack.
4. \left(x\middle|y\right) строит настоящий MiddleAtom и тоже «падает» только под fuzzer → ломается сама машинерия dynamic_cast/RTTI, а не «повреждённый атом».
5. В бэктрейсе два __dynamic_cast (статический в harness_fuzz + системный libstdc++): -fsanitize=fuzzer линкует вторую копию C++ RTTI, которая расходится с системной, и dynamic_cast по множественно-наследуемой иерархии атомов ходит по чужому type_info → SEGV @0x0d на валидных объектах.

Импакт на продукт: НУЛЕВОЙ. В клиенте Telegram нет libFuzzer-рантайма — dynamic_cast работает, \substack/\color рендерятся нормально.

Это ровно та ошибка, от которой ты предостерегал на примере rlottie — «RCE» оказался бутала известный gotcha с новой критической находкой и подняла его до «crediblyCritical». Исправил в setup/FINDINGS.md и записал матрицу в findings/fopen1_FALSE_POSITIVE.md.
